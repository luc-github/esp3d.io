## About the Lua interpreter

ESP3D-X embeds a **Lua 5.4** scripting engine that can execute Lua scripts directly on the device. Scripts run asynchronously in a dedicated task and can communicate with the connected machine (FluidNC, grblHAL, …) through the ESP3D-X message bus.

Lua is a lightweight, high-level, multi-paradigm programming language designed for embedded use. Please refer to [Lua](https://www.lua.org/) for more information about the language itself.

In addition to the standard Lua libraries, ESP3D-X exposes a few additional functions and constants that let a script interact with the machine and the board's GPIO.

## Standard Lua libraries

The following standard Lua libraries are available to scripts:

`base`, `table`, `string`, `math`, `utf8`.

<Aside type="caution">
  For safety and memory reasons, the `io`, `os`, `package`, `debug` and `coroutine` libraries are intentionally **not** loaded.
</Aside>

## Running scripts

Scripts are executed from the filesystem using ESP3D commands:

<div class="rounded-table">
<table class="table-compact">
  <thead>
    <tr>
      <th>Command</th>
      <th>Description</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td><code>[ESP300]&lt;path&gt;</code></td>
      <td>Execute the script located at <code>&lt;path&gt;</code> (e.g. <code>[ESP300]/fs/script.lua</code>).</td>
    </tr>
    <tr>
      <td><code>[ESP301]</code></td>
      <td>Query the interpreter status (<code>idle</code> / <code>running</code> / <code>paused</code> / <code>error</code>).</td>
    </tr>
    <tr>
      <td><code>[ESP301]action=PAUSE</code></td>
      <td>Pause the running script at the next checkpoint.</td>
    </tr>
    <tr>
      <td><code>[ESP301]action=RESUME</code></td>
      <td>Resume a paused script.</td>
    </tr>
    <tr>
      <td><code>[ESP301]action=ABORT</code></td>
      <td>Stop the running script immediately.</td>
    </tr>
    <tr>
      <td><code>[ESP420]</code></td>
      <td>System status — shows <code>lua: idle</code> or <code>lua: running (&lt;path&gt;)</code>.</td>
    </tr>
  </tbody>
</table>
</div>

## Autostart

A script can be launched automatically at startup. This is defined at build time in `customizations/lua/customizations.h`:

```c
#define ESP3D_LUA_AUTOSTART_SCRIPT "/fs/init.lua"
```

The autostart script runs asynchronously and does not block the boot sequence.

## Limitations

<div class="rounded-table">
<table class="table-compact">
  <thead>
    <tr>
      <th>Constraint</th>
      <th>Value</th>
    </tr>
  </thead>
  <tbody>
    <tr><td>Concurrent scripts</td><td>1 (a new run is rejected while one is active)</td></tr>
    <tr><td>Maximum script file size</td><td>2048 bytes</td></tr>
    <tr><td>Maximum incoming message size</td><td>128 bytes (longer messages are truncated)</td></tr>
    <tr><td><code>analogWrite</code></td><td>not implemented (LEDC conflict with buzzer)</td></tr>
    <tr><td><code>analogRead</code></td><td>not implemented</td></tr>
  </tbody>
</table>
</div>

<Aside type="note">
  Because a script runs in an independent task, use `delay(ms)` or `yield()` inside long loops to avoid triggering the ESP32 watchdog.
</Aside>

<Aside type="caution">
  The Lua interpreter requires the `LUA_INTERPRETER_SERVICE` feature to be enabled at build time. On Bluetooth-only builds, free memory is limited — use scripting with caution.
</Aside>
